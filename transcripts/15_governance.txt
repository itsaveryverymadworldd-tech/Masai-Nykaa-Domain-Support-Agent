one-paragraph explanation of the guard:
  Only the Lookup Agent may call check_order_status. This is enforced in
  two independent places rather than by convention: the crew builder
  constructs the tool once and attaches it to the Lookup Agent alone, and
  enforce_tool_ownership() re-checks every agent's tool list before the
  crew is built, raising LeastAutonomyViolation if a privileged tool is
  ever wired to a non-owner. The second check is what makes this a guard
  rather than a comment: a future edit that adds the tool to the Composer
  for convenience would fail loudly at construction time instead of
  silently widening the blast radius. The Retrieval and Composer agents
  are therefore structurally incapable of reading order records, so a
  prompt-injection attempt aimed at the retrieval path cannot reach them.

# APPLICATION LAYER -- RISK CLASSIFICATION
##############################################################################
    Low     summarisation, transcription
    Medium  code generation, customer support tickets <== THIS SYSTEM
    High    medical data, hiring decisions, financial data

CLASSIFICATION: Medium

justification:
  This system is classified **Medium** risk.
  It handles customer support tickets: it answers policy questions and reports the status of one order at a time, which is squarely the 'customer support tickets' example the brief places at Medium.
  It is not Low risk, because the answers drive real customer expectations about refunds, returns and delivery windows -- a confidently wrong answer has a direct commercial cost, which is why the output-side groundedness guard exists.
  It is not High risk, because it handles no medical data, makes no hiring decisions, and touches no financial data beyond the value already printed on the customer's own order: it never sees a full card number (only the last four, masked on input), never initiates a payment, and cannot change an order's state.
  The Medium classification is what justifies the operational controls actually implemented here: an independent second-agent review stage before any answer is released, least-autonomy tool wiring, and a hard per-request budget cap.
